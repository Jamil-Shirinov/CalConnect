# CalConnect Frontend v1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A clickable, student-facing CalConnect app (web + phone from one Expo codebase) with Home/Login/Signup and an 8-section app shell, driven by in-memory mock data.

**Architecture:** Expo Router file-based routes under `frontend/app/`, split into `(auth)` and `(app)` groups whose layouts redirect on sign-in state. All state lives in one React context + pure reducer (`store/AppStore.tsx`) seeded from `data/mock.ts`; date math, filtering and validation are pure functions in `lib/` so they are unit-tested without rendering. Screens are thin: they read the store, call `lib/` helpers, and compose small components from `components/`.

**Tech Stack:** Expo (latest SDK), Expo Router, TypeScript strict, react-native-web, `@expo-google-fonts/inter`, `StyleSheet` + theme tokens, `jest-expo`, `@testing-library/react-native`, `expo-router/testing-library`.

**Spec:** `docs/superpowers/specs/2026-10-19-frontend-design.md`

## Global Constraints

- All work lives in `frontend/`; run every command from `frontend/`.
- TypeScript `strict: true`; gates are `npx jest` and `npx tsc --noEmit` — both must pass at the end of every task.
- No UI component library; plain `StyleSheet` + tokens from `theme/`. No hard-coded hex colors outside `theme/colors.ts`.
- Colors (verbatim): navy `#1B0A5C`, gold `#C4A74F`, goldBright `#E8C245`, cream `#F8E9A8`, skyLight `#CFE8EC`, grey `#D9D9D9`, greyDark `#A6A6A6`, white `#FFFFFF`.
- Font Inter 400/600/700 (`Inter_400Regular`, `Inter_600SemiBold`, `Inter_700Bold`). Spacing scale 4/8/12/16/24/32.
- Wide layout = window width ≥ 768.
- Dates are ISO strings `YYYY-MM-DD` everywhere; parse/format with local `Date(y, m-1, d)` components, never `new Date('YYYY-MM-DD')` (that parses as UTC and shifts a day in US time zones).
- "Today" comes from `state.today` (store), never from `new Date()` inside a screen, so tests are deterministic.
- Never put test files under `app/` (Expo Router treats every file there as a route). Unit tests: `lib/__tests__/`, `store/__tests__/`; screen/component tests: `__tests__/`.
- Memory-only state; reload resets. No network calls.
- Validation runs on submit; buttons stay enabled; errors render inline under the field and clear when that field is edited.

## Review Focus

1. Whitespace-only or space-padded input (`"  "` as a name, `" a@b.co "` as email) — whitespace-only counts as empty; email is trimmed before format check. Pinned in Task 2.
2. Pressing **Request session** twice with the same tutor/date/course — no duplicate pending request. Pinned in Task 4 (reducer) and Task 8.
3. Sending an empty or whitespace-only message — nothing is appended. Pinned in Task 4 (reducer) and Task 9.
4. "Filter by max rate" checked but rate field empty or non-numeric (`"abc"`) — rate filter is ignored rather than hiding every tutor. Pinned in Task 3 (`parseRate`).
5. Calendar paging across a year boundary (Dec → Jan, Jan → Dec) and tapping past days — paging lands in the right year; past days are not selectable. Pinned in Task 2 (`addMonths`) and Task 11.

### Task 2: Pure helpers — `lib/calendar.ts` and `lib/validation.ts`

**Files:**
- Create: `lib/calendar.ts`, `lib/validation.ts`, `lib/__tests__/calendar.test.ts`, `lib/__tests__/validation.test.ts`

**Interfaces:**
- Produces (`lib/calendar.ts`):
  - `type DateRange = { from: string | null; to: string | null }`
  - `toISO(d: Date): string` — local components, zero-padded
  - `todayISO(): string` — `toISO(new Date())`; only called when building the default store state
  - `addDays(iso: string, n: number): string`
  - `addMonths(year: number, month: number, delta: number): { year: number; month: number }` — `month` is 1–12
  - `monthGrid(year: number, month: number): (string | null)[]` — Sunday-first; leading `null`s for days before the 1st, trailing `null`s so length is a multiple of 7
  - `selectDate(range: DateRange, iso: string): DateRange` — no `from` → `{from: iso, to: null}`; `from` set and no `to`: `iso < from` → `{from: iso, to: null}`, else `{from, to: iso}` (same day allowed); both set → restart `{from: iso, to: null}`
  - `inRange(iso: string, range: DateRange): boolean` — inclusive; `to: null` means single day `from`; `from: null` → false
  - `monthLabel(year: number, month: number): string` — e.g. `"October 2026"`
- Produces (`lib/validation.ts`):
  - `type FieldErrors<K extends string> = Partial<Record<K, string>>`
  - `isEmail(s: string): boolean` — trims, then `/^[^\s@]+@[^\s@]+\.[^\s@]+$/`
  - `validateLogin(v: { email: string; password: string }): FieldErrors<'email' | 'password'>`
  - `validateSignup(v: { email: string; password: string; confirm: string }): FieldErrors<'email' | 'password' | 'confirm'>`
  - `validateFeedback(v: { name: string; email: string; subject: string; message: string }): FieldErrors<'name' | 'email' | 'subject' | 'message'>`
  - Exact messages: `'Email is required'`, `'Enter a valid email'`, `'Password is required'`, `'Password must be at least 8 characters'`, `'Passwords do not match'`, and for feedback `'Name is required'`, `'Subject is required'`, `'Message is required'`. Required = non-empty after `trim()`. An empty object means valid.

### Task 4: App store (reducer, provider, test utils)

**Files:**
- Create: `store/AppStore.tsx`, `store/__tests__/reducer.test.ts`, `test-utils/render.tsx`

**Interfaces:**
- Consumes: `MockData`, types and `buildMockData` (Task 3); `todayISO` (Task 2).
- Produces (`store/AppStore.tsx`):
  - `interface FeedbackForm { name: string; email: string; subject: string; message: string }`
  - `interface AppState extends MockData { signedIn: boolean; today: string; feedback: FeedbackForm[] }`
  - `createInitialState(today: string): AppState` — `signedIn: false`, `feedback: []`, rest from `buildMockData(today)`
  - `type Action = | { type: 'signIn'; email: string } | { type: 'signOut' } | { type: 'sendRequest'; tutorId: string; date: string; course: string } | { type: 'checkIn'; sessionId: string } | { type: 'sendMessage'; threadId: string; text: string; at: string } | { type: 'submitFeedback'; form: FeedbackForm } | { type: 'updateProfile'; partial: Partial<Student> }`
  - `appReducer(state: AppState, action: Action): AppState` — pure. `signIn` sets `signedIn` and `student.email` (trimmed). `sendRequest` appends `{ id: 'req-' + (requests.length + 1), status: 'pending', ... }` unless a pending request with the same tutorId/date/course exists (then returns `state` unchanged). `sendMessage` trims text; empty → `state` unchanged; else appends `{ from: 'me', text, at }`.
  - `AppStoreProvider({ initialState?: AppState; children })` — default `createInitialState(todayISO())`
  - `useAppStore(): { state: AppState; signIn(email: string): void; signOut(): void; sendRequest(tutorId: string, date: string, course: string): void; checkIn(sessionId: string): void; sendMessage(threadId: string, text: string): void; submitFeedback(form: FeedbackForm): void; updateProfile(partial: Partial<Student>): void }` — `sendMessage` supplies `at: new Date().toISOString()`; throws if used outside the provider.
  - Derived selectors (exported, pure): `isUnread(thread: Thread): boolean` (last message from `'them'`), `upcomingSessions(state): Session[]` (`date >= today && !checkedIn`, sorted by date then start).
- Produces (`test-utils/render.tsx`):
  - `TEST_TODAY = '2026-10-19'`
  - `makeState(overrides?: Partial<AppState>): AppState` — `createInitialState(TEST_TODAY)` with `signedIn: true`, then overrides
  - `renderWithStore(ui: ReactElement, state?: AppState)` — RNTL `render` wrapped in provider
  - `renderApp(initialUrl: string, state?: AppState)` — `renderRouter` from `expo-router/testing-library` with a route map built from the real route modules: `_layout` (provider + `<Slot/>`, no font loading), `(auth)/_layout`, `(auth)/index`, `(auth)/login`, `(auth)/signup`, `(app)/_layout`, and each `(app)/<screen>`.
